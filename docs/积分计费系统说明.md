# 积分计费系统说明

## 一、系统架构概述

本项目采用**双轨计费系统**：

1. **现金计费（旧版）**：基于人民币金额的计费，记录在 `balanceTransaction` 表的 `type: 'consume'` 记录
2. **积分计费（新版）**：基于用户积分的计费，记录在 `balanceTransaction` 表的 `type: 'credit_deduct'` 记录

---

## 二、积分计费流程

### 2.1 核心流程（三阶段扣费）

```
任务提交
   ↓
冻结积分（freezeCredits）
   ↓
   ├─ 成功：扣除冻结的积分（confirmCreditDeduct）
   └─ 失败：解冻积分（unfreezeCredits）
```

### 2.2 冻结积分 (freezeCredits)

**文件**：`src/lib/credit-billing/service.ts`

**作用**：任务提交时，预估需要消耗的积分并冻结。冻结期间积分不可用但未实际扣除。

**参数**：
```typescript
{
  userId: string           // 用户 ID
  credits: number          // 要冻结的积分数量（预估）
  options: {
    source?: string        // 来源：video / image / audio / voice_design / lipsync
    taskId?: string        // 关联任务 ID
    requestId?: string     // 请求 ID
    idempotencyKey?: string // 幂等键
    metadata?: Record<string, unknown> // 计费元数据
  }
}
```

**数据库记录**：
- `balanceFreeze` 表：创建冻结记录
- `balanceTransaction` 表：创建 `type: 'credit_freeze'` 流水（amount = 0）

**余额变更**：
```
userBalance.subscriptionCredits -= credits  // 或 permanentCredits
userBalance.frozenCredits += credits
```

### 2.3 确认扣费 (confirmCreditDeduct)

**文件**：`src/lib/credit-billing/service.ts`

**作用**：任务成功完成后，根据实际消耗量确认扣费。

**逻辑**：
1. 读取 freeze 记录（状态必须为 pending）
2. 计算实际消耗：`chargedCredits = 实际计算得出的积分`
3. 退还剩余积分：`refundCredits = frozenCredits - chargedCredits`（如果 > 0）
4. 更新冻结状态为 confirmed
5. 减少 frozenCredits
6. 创建 balanceTransaction 流水（type: credit_deduct, amount = 0）

**关键字段（billingMeta）**：
```json
{
  "frozenCredits": 100,    // 原冻结数量
  "chargedCredits": 80,    // 实际扣费
  "refundCredits": 20      // 退还数量
}
```

### 2.4 解冻积分 (unfreezeCredits)

**文件**：`src/lib/credit-billing/service.ts`

**作用**：任务失败时，全额解冻冻结的积分。

## 三、扣费场景与定价

### 3.1 积分定价配置

**配置键**：`billing.credit_pricing`（SystemConfig 表）

**默认值**：
```typescript
{
  image: { basic: 1, advanced: 3 },         // 图片生成（单位：积分/张）
  video: { basic_per_sec: 5, advanced_per_sec: 20 }, // 视频生成（单位：积分/秒）
  text: { per_1000_chars: 2 },              // 文本生成（单位：积分/千字）
  audio: { per_10_sec: 2 },                  // 音频生成（单位：积分/10秒）
  voiceDesign: { per_call: 5 },              // 音色设计（单位：积分/次）
  lipSync: { per_call: 10 },                 // 口型同步（单位：积分/次）
}
```

**模型档次映射**：`billing.model_tier_map`
- 根据模型 ID 映射到 `basic` 或 `advanced` 档次
- 用于区分不同模型的定价档位

### 3.2 主要扣费场景

| 场景 | 触发位置 | 调用方 | 单位 |
|------|----------|--------|------|
| **图片生成** | Character、Location、Storyboard 等 Worker | Worker | 积分/张 |
| **视频生成** | Video Worker | Worker | 积分/秒 |
| **音频生成** | Audio Worker | Worker | 积分/10秒 |
| **音色设计** | Voice Design Worker | Worker | 积分/次 |
| **口型同步** | LipSync Worker | Worker | 积分/次 |
| **LLM 调用** | Analysis、各种 Prompt 任务 | 各个组件 | 按调用量 |

### 3.3 计费调用链

**典型视频生成流程**：
```
NovelPromotion Workflow
  ├─ 文本分析（LLM）→ 冻结 + 扣费
  ├─ 人物角色图生成 → 冻结 + 扣费
  ├─ 场景背景图生成 → 冻结 + 扣费
  ├─ 分镜图像生成 → 冻结 + 扣费
  ├─ 视频片段生成 → 冻结 + 扣费
  ├─ 配音生成 → 冻结 + 扣费
  └─ 口型同步 → 冻结 + 扣费
```

## 四、数据库表结构

### 4.1 balanceFreeze（积分冻结表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 主键 |
| userId | String | 用户 ID |
| amount | Decimal | 冻结积分数量 |
| status | String | pending / confirmed / rolled_back |
| source | String | 来源类型 |
| taskId | String | 关联任务 ID |
| requestId | String | 请求 ID |
| idempotencyKey | String | 幂等键 |
| metadata | String(JSON) | 计费元数据：包含 model、quantity、unit 等 |
| createdAt | DateTime | 创建时间 |
| updatedAt | DateTime | 更新时间 |

### 4.2 balanceTransaction（积分流水表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 主键 |
| userId | String | 用户 ID |
| type | String | credit_freeze / credit_deduct / credit_unfreeze / recharge / grant |
| amount | Decimal | **注意**：积分计费时 amount = 0，实际消耗在 billingMeta 中 |
| balanceAfter | Decimal | 余额快照（积分计费时 = 0） |
| description | String | 描述 |
| relatedId | String | 关联 ID |
| freezeId | String | 关联冻结记录 ID |
| operatorId | String | 操作人 ID（后台充值时使用） |
| projectId | String | 项目 ID |
| episodeId | String | 集数 ID |
| taskType | String | 任务类型 |
| billingMeta | String(JSON) | 计费详情 |
| createdAt | DateTime | 创建时间 |

**billingMeta 字段说明**：

**对于 credit_deduct 类型**：
```json
{
  "frozenCredits": 100,      // 原冻结积分
  "chargedCredits": 80,      // 实际扣费积分
  "refundCredits": 20,       // 退还积分
  "model": "doubao-seed-2-0", // 模型名称
  "apiType": "video",        // API 类型
  "quantity": 4,             // 数量
  "unit": "sec"              // 单位
}
```

**对于 consume 类型（现金计费）**：
```json
{
  "model": "ark::doubao-seed-2-0",
  "apiType": "video",
  "quantity": 4,
  "unit": "sec",
  "resolution": "2K"
}
```

### 4.3 userBalance（用户余额表）

| 字段 | 类型 | 说明 |
|------|------|------|
| userId | String | 用户 ID（主键） |
| subscriptionCredits | Int | 订阅套餐积分 |
| permanentCredits | Int | 永久有效积分（充值获得） |
| frozenCredits | Int | 冻结中积分 |
| totalSpent | Decimal | 累计消费金额（现金） |
| totalRecharged | Decimal | 累计充值金额 |
| balance | Decimal | 现金余额（旧系统） |
| createdAt | DateTime | 创建时间 |
| updatedAt | DateTime | 更新时间 |

**积分扣减优先级**：优先扣减 subscriptionCredits（订阅积分），扣完再扣 permanentCredits（永久积分）

## 五、消费明细 API

**接口**：`GET /api/user/usage?days=30`

### 5.1 响应结构

```json
{
  "success": true,
  "data": {
    "overview": {
      "totalCredits": 15000,        // 总积分
      "availableCredits": 12984,    // 可用积分
      "frozenCredits": 0,           // 冻结中积分
      "totalSpent": 0,              // 累计消费金额
      "periodUsage": 2016,          // 周期内使用积分
      "periodTaskCount": 15,        // 周期内任务数
      "subscription": { ... }       // 订阅信息
    },
    "trend": [                       // 每日使用趋势
      {"date": "2026-05-13", "totalCredits": 200, "taskCount": 3}
    ],
    "details": {
      "list": [                       // 消费明细列表
        {
          "id": "...",
          "projectId": "...",
          "model": "doubao-seed-2-0",
          "action": "video_generate",
          "cost": 80,                // 消耗积分
          "isCredit": true,          // 是否为积分计费
          "createdAt": "2026-05-13T10:30:00Z"
        }
      ],
      "pagination": { ... }
    }
  }
}
```

### 5.2 关键逻辑说明

1. **双类型兼容**：同时查询 `type: 'consume'`（现金）和 `type: 'credit_deduct'`（积分）两种交易
2. **Decimal 精度处理**：现金计费的 amount 可能存在精度问题（如 7.938 存储为 7938000），API 会自动除以 1000000 并取整
3. **积分消费取数**：积分消费从 `billingMeta.chargedCredits` 或 `billingMeta.credits` 读取
4. **关联 freeze 记录**：通过 freezeId 关联查询 balanceFreeze 表获取完整元数据

```

   ↓
```

## 九、已知问题与注意事项

### 9.1 Decimal 精度问题

**问题**：
- 旧版现金计费中 `amount` 字段为 Decimal 类型
- 部分场景下可能出现精度放大（如 7.938 → 7938000）
- 原因：MySQL Decimal 与 Prisma Client 之间的转换问题

**临时处理**：
API 层对 > 100000 的数值自动除以 1000000

```typescript
const rawAmount = Math.abs(record.amount.toNumber())
const cost = rawAmount > 100000 ? Math.round(rawAmount / 1000000) : rawAmount
```

### 9.2 credit_deduct 的 amount = 0 问题

**问题**：
积分消费时 `balanceTransaction.amount` 被硬编码为 0，实际消耗存储在 `billingMeta.chargedCredits`

**影响**：
- 统计时不能直接用 `SUM(amount)`
- 需要解析 JSON 字段进行计算

### 9.3 历史数据兼容

- 系统中可能同时存在现金计费和积分计费的历史数据
- 消费明细 API 需要同时兼容两种数据格式
- 显示时统一为"积分"单位，现金数据需按汇率转换（待完善）

## 十、未来优化方向

1. **统一计费口径**：完全迁移到积分计费，停用 cash-based billing
2. **消费分类统计**：按项目、按模型、按时间段进行多维度统计
3. **消费预警**：积分不足时自动提醒
4. **消费导出**：支持导出 CSV 账单
5. **订阅积分过期处理**：每月自动清零上月未使用的订阅积分
6. **发票管理**：充值开票功能
